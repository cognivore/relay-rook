OpenWV setup for Chrome on macOS

OpenWV replaces Chrome’s Widevine CDM library. A .wvd device provision supplies the identity used to request licenses. OpenWV requires you to provide that file and embeds it when compiling. Upstream requirements.

Required before building: your own valid device provision. The EME logs supplied during setup contain initialization data, public certificates and encrypted license messages. They do not supply this private identity. The build stops before fetching source if the device file is missing or invalid.

1. Prepare a private build

Relay Rook’s build script uses Rust, Cargo, Clang and Python supplied by Nix. It checks out a pinned OpenWV revision and uses Cargo’s lockfile. Replace the device path below with your actual file; choose a new output directory.

cd ~/Github/relay-rook
nix develop .#openwv -c bash archive/build-openwv.sh \
  /private/path/device.wvd \
  "$HOME/Movies/Relay Rook/.relay-rook/openwv-build"

The device file must have permissions 600. The build directory is private, existing output is never overwritten, and the temporary embedded.wvd source copy is removed when compilation exits. The compiled library and build artifacts still contain the identity: keep the entire build private and outside Git and the Nix store.

Build status: the build entry point and its failure checks are prepared. A working OpenWV library has not been built or tested here because no device provision has been supplied.

2. Review the Chrome package

A successful native Apple Silicon build prepares:

openwv-build/chrome/9999/
  manifest.json
  _platform_specific/mac_arm64/libwidevinecdm.dylib

Native Intel builds use mac_x64. Chrome must run the same architecture as the library. The script prepares files; it does not modify Chrome.

3. Install and verify in Chrome

  1. Open chrome://version. The parent of Profile Path is the user data directory. Confirm Chrome’s architecture matches the package.
  2. Quit Chrome completely. Move its existing WidevineCdm directory to a private backup location outside the user data directory.
  3. Create a new WidevineCdm directory and copy the prepared 9999 directory into it.
  4. Restart Chrome. Check chrome://components, then test the purchased video. Preserve the exact playback error if the provider rejects the new identity.

Upstream Chrome layout. These instructions preserve a backup instead of deleting the existing component. To undo the change, quit Chrome, move the OpenWV directory aside and restore the backup to its original location.

4. Verify the archive separately

OpenWV’s Chromium manifest declares x-cdm-persistent-license-support: false. Installing it does not automatically create offline Chrome playback. Manifest.

Relay Rook’s helper is a separate license client. It can use the same local .wvd file through --device, but it does not automatically receive Chrome’s decrypted keys. Provider acceptance must be checked for each client. The archive is successful only when a video is saved and its audio/video verification passes.

The helper’s decryption and verification stages have passed generated-media checks, including a wrong-key test. No key for the purchased course has been acquired, and replacing Chrome’s CDM has not been verified to resolve that.
